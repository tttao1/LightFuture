# 修复 GitHub 首次构建的 Flutter 测试失败

2026 年 10 月 7 日，首次云端运行显示 6 项测试通过、5 项失败。已使用 Flutter 3.35.7 在本机复现同样结果，修复后 11 项测试全部通过，flutter analyze 显示 No issues found。

## 失败原因

四项控制器测试仍有活跃定时器，但把释放操作放在 addTearDown 中。Flutter 的测试结束检查先于该回调执行，因此报错 A Timer is still pending even after the widget tree was disposed。现在在每项测试的 try/finally 中释放控制器，确保框架进行检查前已经取消定时器，断言失败时也可以清理。

暂停界面测试在 AppLifecycleState.paused 状态下检查文字，而后台状态不绘制新画面，因而找不到“训练已暂停”。现在先模拟退到后台，等待十秒，再模拟回到前台并刷新画面，随后检查暂停状态、继续训练和重新倒计时。

游戏逻辑、界面和 GitHub 工作流未改动，原有测试断言均保留，没有跳过测试。

## 需要更新的两个文件

- test/reaction_controller_test.dart
- test/widget_test.dart

本地最新文件位于 D:\pycharm\LightFuture\test。也提供 dist/lightfuture-demo-test-fix.zip，只包含这两个文件，解压后保留 test 目录。

## 使用 GitHub 网页更新

1. 打开 LightFuture 仓库的 Code 页面，进入 test 目录。
2. 点击 Add file → Upload files。
3. 上传本地最新的 reaction_controller_test.dart 和 widget_test.dart 两个文件，不拖入外层 test 文件夹，避免形成 test/test 嵌套。
4. 提交到 main 分支，覆盖仓库里同名文件。
5. 进入 Actions，查看这次新的运行。提交改变了 test 目录，因此会自动触发构建。
6. 先确认 Run game and widget tests 全部通过，再等待后面的 APK 编译、签名及权限验证完成。
7. 整次运行绿色成功后，在 Artifacts 下载 lightfuture-demo.apk，按原教程安装到手机。

如果采用 Create new file／Edit file 手工复制内容，必须使用上述完整文件路径并复制最新文件全部内容。
